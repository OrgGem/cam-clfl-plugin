# Local-first trust boundaries

The active application has no hosted database, app-user identity service, vendor credential proxy or telemetry. Tokens are obtained with public-client PKCE, kept in the OS vault and sent only to Cloudflare token/userinfo/API/revoke endpoints. Fixed HTTPS origins, redirect rejection, 15-second timeouts and bounded JSON responses prevent arbitrary URL forwarding. OS/network/proxy configuration remains controlled by the device owner.

The loopback UI never receives access/refresh tokens. Neither MCP schemas nor UI APIs accept arbitrary credential objects, user IDs, SQL, JavaScript or Cloudflare API paths. OAuth configuration accepts a public client ID and scope string, not a client secret. Resource allowlists strip unrecognized upstream fields before inventory results reach the model. Authorized DNS record content itself may be sensitive and is intentionally visible in reads/previews; credential custody does not imply all resource data stays outside the conversation.

OAuth state is one-time, browser-bound and expires in ten minutes. PKCE verifier remains in process memory; token exchange uses `none` client authentication. Identity comes from the access-token-authenticated Cloudflare userinfo endpoint. No Google ID token or local fake login is used. Reconnect checks the same Cloudflare subject, and discovery/confirmation determine usable accounts. Target IDs are explicit on every resource call and zones are checked against their account.

Local API requires a one-time launch-ticket bootstrap followed by an HttpOnly same-site session. Host and mutation Origin checks prevent ordinary cross-site loopback requests and DNS rebinding; CSP blocks framing and external browser resources. Listener is hard-bound to IPv4 loopback, and no CORS, tunnel or remote MCP endpoint is exposed. Tickets never enter model/tool results. Browser tickets/cookies authorize local UI actions and are secrets even though they are not Cloudflare credentials.

Production has no environment flag for a memory/plaintext credential fallback. Test-only injected vault/network implementations reside in tests and are excluded from the emitted runtime. Linux pins Secret Service rather than allowing volatile keyutils fallback. Native backend behavior and signing/distribution must be accepted separately on each supported OS; source tests do not establish a trusted desktop installer.

The local operation journal prevents normal replay and process-crash retries, not malicious rollback by a process with access to the same OS user or a restored old filesystem snapshot. A malicious same-user process could alter the journal or use the OS vault; protecting against that requires additional OS isolation/hardware controls. Lock recovery is a manual, single-operator action after stopping other companion/MCP processes. Local writes are serialized, reads may overlap; 429 is sanitized and callers must back off.

Approvals are local-only, target/payload bound, expiring and consumed through a persisted write-intent status. Production environment changes require a fresh preview. No MCP tool can approve. API verification establishes observed resource state, not global DNS propagation or attribution if an external actor independently made the same change. Unknown outcomes retain blocking journal state and require read-only reconciliation.

Live Cloudflare OAuth, actual platform vault persistence and ChatGPT embedded-only/local-process compatibility are not asserted from mocks. The archived server manager still contains historical backend-storage code for reference, but it is outside active build/runtime/config. Remove/revoke any old hosted deployment separately if one exists; changing this repository does not erase credentials already deployed elsewhere.
